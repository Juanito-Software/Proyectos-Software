chore(java): move the Spring exercises out of the repository

Remove Java/Spring/SpringBatch (12 projects) and Java/Spring/SpringBoot
(ApiService, Soccer, api/ApiExtractData, api/api2/ApiExtractData,
user_management). Spring/docs is kept.

These were course exercises kept side by side as variants, and the
duplication had a measurable cost. CodeQL reported "166 duplicate classes
filtered out": nine copies of the Spring Batch exercise declared the same
fully-qualified class names, so only one of each clashing pair was ever
analysed. The Java analysis had a blind spot from the start.

That blind spot was hiding real defects. A grep across the unscanned
copies found the same path traversal that CodeQL had reported in
FalsosBatch -- an HTTP @RequestParam flowing straight into a filesystem
path -- in four more controllers that never appeared in any alert list:

  General/Api_para_lectura/.../BatchController.java:76
  Por_lotes_enLinea/.../BatchController.java:49
  Por_lotes_enLinea/paralelo/.../BatchController.java:49
  Por_lotes_enLinea/sin duplicados/.../BatchController.java:75

The same applied to api/ApiExtractData and api/api2/ApiExtractData: two
diverging versions sharing every class name, only one of which was
scanned.

Removing them resolves the blind spot at its source rather than working
around it, and drops the Maven advisories that lived in those poms
(mysql-connector-java, log4j-core, jackson-databind, jackson-core).

The code remains reachable in history; this is a working-tree removal, not
a history rewrite.
